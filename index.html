How this stops bots in production

Layer 1 · invisibleSilent signalsHidden honeypot field, time on page, mouse / touch activity, typing, automation flags and repeat attempts give every checkout a risk score.
Layer 2 · visibleRotating human checks8 quick puzzles picked at random, so a bot can't learn one pattern. Higher risk means more puzzles. 3 failures lock checkout for a while.
Layer 3 · serverServer-side verificationIn the live build, puzzles and answers are created and checked on our server with a one-time token, so the answer is never in the page.
Layer 4 · paymentStripe Radar + 3D SecureVelocity rules (cards / emails per IP), block highest risk, 3D Secure on elevated risk. Delay eSIM delivery for flagged orders.
Layer 5 · edgeRate limitsCloudflare limits on checkout and payment calls per IP and device stop bursts before they reach our site.

This page is a clickable prototype. The checks run in the browser so they can be shown live; the production version moves scoring and puzzle checks to the server.
